HOW THE DATA GETS THERE
-----------------------
LeadCapture puts the answers in the URL -> thankyou.html captures them
-> builds the Ferrylend iframe src from them.

### YOU MUST FILL IN ONE TABLE ###

Near the bottom of thankyou.html, find FERRYLEND_MAP. It looks like:

    var FERRYLEND_MAP = {
      "Name":          "",      <- first name
      "Last Name":     "",
      "Email":         "",
      "Phone Number":  "",
      ...
    };

LEFT side  = your LeadCapture field names. Already correct, taken
             straight from the live funnel. Do not change these.
RIGHT side = what Ferrylend calls the same field. YOU FILL THESE IN.

Get them from Ferrylend support, or open ferrylend.com/apply/lendihub
in a browser, right-click > View Source, and read the name="..." on
each input.

Ferrylend's apply page blocks automated reading, so I could not look
them up and I was not willing to guess. Until you fill the table in,
the form loads and works normally, it just does not pre-fill. Nothing
breaks in the meantime.

Edit only the right-hand side, keep the quotes, save, redeploy.

FERRYLEND_FORWARD_UNMAPPED is set to false. Flip it to true if you want
every unlisted parameter passed through under its own name as well.
Leave it false until you know Ferrylend ignores parameters it does not
recognise.

A PRIVACY PROBLEM I FIXED WHILE BUILDING THIS
---------------------------------------------
This page runs your Meta Pixel. Had the lead data simply sat in the
address bar, the pixel would have sent the full URL to Meta on every
page view -- names, phone numbers, email addresses and revenue figures,
straight into Meta. That breaks Meta's own rules and it is not covered
by your privacy policy.

So the very first script in <head>, BEFORE the pixel loads, reads the
query string into memory and then wipes it out of the address bar with
history.replaceState. The pixel sees a clean URL. The data is still
available to build the iframe.

Verified: arriving at the page with eight parameters leaves the address
bar reading "thankyou.html" with no query string at all, while the
iframe still receives every mapped value.

Side benefit: the data is no longer in browser history or in the
referrer header, and it will not be read back by anyone who hits the
back button on a shared computer.
